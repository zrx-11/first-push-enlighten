# 复杂的引擎 模式与框架库

## 分析框架：四问判断一个过程是否为“引擎”

有没有复制？副本之间有没有差异？差异是否影响留存？留存的优势是否能进入下一轮？四问全“是”，才配得上“进化/引擎”这个词。

## 分析框架：结构来源判别

看形态是否由对称性与能量最低决定 → 免费结构；看形态是否服务于某个功能、需要步骤才能造出 → 目的性结构；两者都有 → 分层解释，别用一个词糊过去。

## 决策规则：评估函数优先

if 你要用算法进化/训练得到某个能力
  then 先把该能力写成可测分数，并检查有没有被漏掉的性质
  if 分数只覆盖一部分
  then 结果一定会利用漏洞

## 反模式：把负熵当复杂度

有序 ≠ 复杂。晶体熵极低却简单。要区分“简单有序”与“精巧组织”，必须引入描述长度或生成步骤。

## 反模式：把拟子当基因

文化单位没有清晰边界与物理载体，不能直接套用基因的频率、适应度算法。当启发式用，别当理论用。
